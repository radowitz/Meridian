## 同一次测试里手工核对过、没有单独日志的

- 迁移：旧的 pool 变成 10 个地区组（含由 `pin` 规则拆出的手动组），15 条规则、12 个节点随之改写。
- 密钥登录：面板生成 ed25519 密钥；指纹确认前连接测试被 409 拒绝；「发现指纹」返回的值与主机真实的主机密钥指纹一致；提交错误指纹被拒；确认后连接测试成功并返回系统、内核和架构。对象是这台网关自己的 sshd。
- 密码登录：对一个只监听回环地址、允许密码的临时 sshd 实例和临时账号走同样的流程，连接测试成功，认证方式显示为密码。这台网关平时的 sshd 不允许密码登录。
- 凭据：密码和设备私钥不在任何 API 响应、面板日志、宿主代理日志和两个数据卷的文件里；秘密文件是 0600；删除仍被服务器引用的凭据返回 409 并列出引用者。

## 这次测试发现并修掉的

- **IPv4 经局域网口转发的流量全部被内核丢弃。** 旧的 `iif <局域网口> unreachable` 规则加上宽松模式的反向路径过滤，会让内核在源地址校验时拒绝每一个从局域网口转发出去的 IPv4 包（`ip route get` 返回 `Invalid cross-device link`）：局域网客户端的国内直连、隧道回程到局域网客户端都不通。这是原始设计里就有的问题，之前没有任何测试检查过 IPv4 的国内路径和回程。规则已删除，IPv4 和 IPv6 一样只靠 `inet meridian_guard`；验收脚本和 netns 测试现在都直接检查这些路径（见架构「局域网兜底」）。上一份记录是在这条规则还在时产生的，而且当时的 netns 测试不检查这些路径。
- netns 测试本身的三处问题：设备的流量要在规则加载之后才开始（真实系统里 `mra` 在规则之后才创建）；充当隧道的 dummy 接口要带上编译配置里的地址（没有 IPv4 地址的接口在源地址校验里走另一条分支）；重载之后要把运行时集合里的测试地址加回去。

## 这次测试看到、在同一批改动里修掉的

- 服务器不提供密码登录时，连接测试报的是「拒绝了密码登录」，看起来像密码错了；现在有单独的错误码，并说明服务器提供哪些登录方式。
- 仅 IPv4 的服务在 IPv6 上被跳过的探测项归类为「未知」；现在是「不适用 · 仅 IPv4」，不计入未知。
- 平板宽度下几张表的名称列被挤成一字一行、操作列被截断；`net.ipv6.conf.*.send_redirects` 这个不存在的设置造成的日志噪音；新加的 ULA netns 测试第一次运行时因为把计数器命名成 nft 的保留字 `fwd` 而加载失败。

## 这次测试看到、没有修的

- 同一条连接中途改变分类时会断。分类标记按包打，地址转换按连接在建立时定下；重载清空运行时集合后，一条持续的连接可能先被当成境外（转换成中转地址），等地址重新进入国内集合后又从局域网口出去，沿用的却是旧的转换，对端的回程回不来，直到这条连接超时。目的地是国内地址，不构成境外泄漏；新建的连接不受影响。
