# 常见问题

## NAT 后面的中继要怎么转发端口

中继（或枢纽、出口）在家用路由器、云厂商的 NAT 后面时，要在 NAT 设备上把它监听的端口转发进来：

- **WireGuard（UDP）**：每条链路在监听的一端有自己的 UDP 端口。没有填 `wg_port` 时，节点只监听一条链路就用节点的 `listen_port`，否则是 `51820 + 链路的分配序号`；`udp_wss_failover` 链路还会占用下一个端口（`wg_port + 1`）。分配序号保存在拓扑里，之后不随增删别的链路变化。
- **WSS（TCP）**：节点的 `wss_listen_port`，模板默认 443。
- **SSH（TCP）**：面板管理这台机器用的端口。

**经验教训：链路实际使用的 UDP 端口必须落在转发范围之内。** 只转发了「看起来对」的一段端口（例如 51820–51830），而面板给某条链路分到了范围外的端口时，握手永远不会成功，WSS 腿看起来正常、UDP 腿一直不通，很难看出原因。做法：

1. 在拓扑页选中链路，看它的 WireGuard 端口（或在链路上显式填 `wg_port`，把端口固定到你转发的范围里）；
2. 在 NAT 设备上转发这个端口，`udp_wss_failover` 时连同 `+1`；
3. 远端预检会列出要监听的端口；装机后在[链路日志](troubleshooting.md#链路日志)里看这条链路的 UDP 腿有没有握手。

出口只能主动拨出、无法被连入时，不需要转发：把链路画成由出口拨向枢纽（NAT 拨出），`PersistentKeepalive` 必须保持打开。

## UDP 被封或很差

网关到中继的 `udp_wss_failover` 链路同时生成 UDP WireGuard 和 WG over WSS（TCP 443 上的 WebSocket，面板生成的自签证书和随机路径）。UDP 握手或探测连续失败时自动切到 WSS，恢复后带滞回切回。只有 WSS 也不通时这条路才算断；有备用枢纽或多台中继时再走那些路径，全部不通则失败关闭。

WSS 不伪装成网站：证书是自签的、SNI 是明文的合成名称。它解决的是「UDP 不通」，不是「对抗识别」。

## MTU 怎么定

默认值按 PPPoE（1492）规划：网关 → 中继 UDP 腿 1412、WSS 腿 1360；中继 → 枢纽、枢纽 → 出口 1420；Mesh 腿按路径 MTU 1280 再扣掉 WireGuard 开销；低于 1280 拒绝。TCP 的 MSS 按每个出口所有可能承载它的路径里最小的值钳制，所以切换路径时不会因为 MTU 变小卡住。

你的上联不是 PPPoE、或者某一跳还有额外封装时，在链路上填 `mtu` / `wss_mtu`。症状通常是：能打开网页首页，但大文件、视频或某些 HTTPS 站点卡住。

## SSH 被限速 / 只能经中继管理

OpenSSH 9.8 起默认开启 `PerSourcePenalties`：同一来源短时间连接多次、或有连接没完成认证（只取主机指纹就断开也算），之后服务器会在版本行之前回 `Not allowed at this time` 并断开。面板把这种情况识别为 `ssh_rate_limited`，提示等待后重试，而不是报成密码错误。经 NAT 端口转发到达的机器最容易遇到，因为所有连接都来自转发器的同一个地址。

管理通道（「服务器」页每台机器的 `channel`）：

- `direct`：直接连地址:端口（默认）。
- `tunnel`：隧道建好后，经网关到这台机器的隧道地址管理。
- `jump`：经一台**受管中继**跳转：先用中继自己的凭据和中继自己已确认的指纹登录中继，再由中继转发到目标；目标的指纹另外核对。不转发任何密钥或 agent。专线机器只能从中继访问时用它。

在服务器上也可以把面板网关的地址（或中继）加入 `PerSourcePenalties` 的豁免，按你自己的安全要求决定。

## IPv6

- **客户端 IPv6 经本网关**（默认关）：手机通常只能手填 IPv4 网关和 DNS，IPv6 仍来自家里路由器。关闭时网关的解析器对国内名单以外的域名不返回 AAAA，境外访问只用 IPv4 进隧道，不会从家里宽带的 IPv6 绕过隧道；国内域名照常有 AAAA。只有设备的 IPv6 默认路由也指向网关时才打开（见[测试设备](../test-device.md)）。
- 隧道内部用 ULA `fd66::/48`。有 IPv6 的出口做 NAT66，没有的出口过滤 AAAA、仍用 IPv4 出去。
- 纯 IPv6 的出口要经双栈中继或 Mesh 腿到达；做不到时面板拒绝保存。
- WebRTC 可能暴露设备自己的 IPv6 地址（host 候选），这一点网关管不了，见[防泄露清单](../verification.md)。

## 国内域名用哪个解析器

国内名单里的域名由网关上的 SmartDNS 交给「国内解析器」，境外域名走隧道内各出口自己的解析器。国内解析器取拓扑页「国内 DoT 解析器」（`settings.domestic_dot`）：

- **向导生成的拓扑不设这一项。** 留空时编译**回退到两家公共解析器 `223.5.5.5` 和 `1.12.12.12`**，网关的 `smartdns.conf` 里对它们各写一行 DoT（`server-tls …:853`）和一行明文 UDP/TCP（`server …`）。也就是说，国内域名的查询会经本地宽带发给这两家，其中一部分是明文。
- 想换成别的解析器（例如运营商或自建的），在拓扑页「国内 DoT 解析器」里填 IPv4 地址后重新编译、安装。填了之后同样对每个地址写 DoT 和明文两行，不再使用上面的两个默认地址。
- 境外域名不受影响：它们只经隧道内的出口解析器查询；「客户端 IPv6 经本网关」关闭（默认）时，国内名单以外的域名不返回 AAAA。

## 面板能从外网访问吗

不要把面板端口转发到公网。面板只监听确认过的局域网地址，宿主防火墙只放行回环、局域网网卡上来自局域网网段的连接、远程接入接口 `mra` 和 `--allow` 来源（见 [install.md](install.md#管理防火墙)）；远程管理请用面板的远程接入（WireGuard）或 `ssh -L 8787:127.0.0.1:8787`。见 [security.md](security.md)。
