# 安全模型与威胁模型

本文说明 Meridian 面板默认怎样保护自己、它握有什么、以及它不防什么。安装与升级的完整步骤见 [quickstart.md](quickstart.md)、[install.md](install.md) 和 [upgrade-rollback.md](upgrade-rollback.md)。

## 面板握有什么

- **全部服务器的 SSH 凭据**：中继、枢纽、出口的地址、用户名、私钥或密码都保存在面板的凭据目录（Docker 命名卷 `meridian-secrets`，目录 0700、文件 0600，不进拓扑快照、不进日志、API 不回显）。拿到面板管理权限或这个卷，就能登录全部服务器。
- **宿主执行权限**：面板通过宿主上以 root 运行的 `meridian-host`（只监听 root 专用的 Unix 套接字）安装和启停网关数据面。面板管理员等同于网关的 root 操作员。
- **Cloudflare 账户令牌、WireGuard 私钥、远程接入密钥**：同样保存在凭据目录。
- **面板口令**：`/var/lib/meridian/panel.token`（0600）。所有 API 请求都带这个 bearer 口令。
- **管理员账户**：`/var/lib/meridian/admin.json`（0600）只存用户名和 scrypt 哈希，不存明文密码。

首次配置向导的进度（`/api/setup/wizard`）只记服务器 ID 和拓扑输入，不存密码或私钥；向导里填的凭据直接进入凭据目录。凭据只在经已确认主机指纹的 SSH 连接上使用，向远端传送的秘密（WSS 证书私钥、外部 SOCKS 凭据等）只在安装边界注入。

备份数据卷和凭据卷时，按私钥对待。

## 默认安全措施

1. **没有默认口令或密码。** 全新安装第一次启动时处于“未初始化”状态：除 `/api/health` 和初始化接口外，所有 API 都返回 `403 setup_required`，不能编译、安装或部署任何东西。
2. **一次性初始化码。** 管理员在网关上运行 `docker compose exec meridian meridian setup-code`，初始化码只显示在这个终端里（1 小时有效）。数据目录只保存它的 SHA-256；连续输错 5 次即作废，需要重新生成。初始化码和密码都不写日志。
3. **初始化只接受局域网来源。** 初始化接口只接受回环、私有地址（RFC 1918、ULA）、链路本地地址和远程接入设备池发来的请求；即使面板被误绑到公网地址，也无法从公网抢先完成初始化。
4. **只监听确认过的地址。** 面板监听 `MERIDIAN_BIND`（安装脚本在操作员确认后写入 `deploy/.env`）；没有时沿用已存拓扑的 `panel_bind`；全新安装两者都没有时只监听 `127.0.0.1:8787`，需要用 `ssh -L 8787:127.0.0.1:8787` 访问。面板拒绝监听 `0.0.0.0` / `::`。
5. **不内置任何网络。** 局域网地址、网段、路由器地址都来自首次配置的输入或经确认的探测结果。拓扑缺少网关局域网地址时，校验报 `missing_gateway_lan`，不会悄悄套用某个内置网段。
6. **登录限速。** 同一来源（IPv4 地址，或 IPv6 的 /64）15 分钟内管理员密码错误 5 次，这个来源锁定一分钟；其他来源不受影响。计数保存在数据目录的 `login-lockout.json`（0600，最多 256 个来源，过期自动清除），面板重启不会清零。

## 宿主防火墙规则契约（由安装脚本落实）

- 面板端口（默认 8787/tcp）只允许：回环；确认的局域网网卡上、且来源是该网卡局域网网段的连接（网卡和来源都要匹配）；远程接入接口 `mra`（不按来源过滤；每个设备对端只被允许使用它在设备池里的地址）；`--allow` 来源（任意接口）。
- 其余来源一律丢弃，包括 WAN 接口和被主路由器转发到局域网网卡上的公网连接；IPv4 和 IPv6 都覆盖，经 DNAT 转发的连接（Docker 发布端口）按同样的规则判断。
- 规则没有通过 `nft -c` 检查时安装中止，面板不启动。
- 不删除、不覆盖非本项目的防火墙规则，保留 SSH 管理通路。

规则的具体内容、文件位置和撤销方法见 [install.md](install.md#管理防火墙)。

## 升级兼容

已有部署（存在 `panel.token`、设置了 `MERIDIAN_TOKEN`，或已经保存过拓扑）升级后**直接视为已初始化**，原口令照常可用，不会因为缺少管理员账户被锁在门外。管理员密码可以之后在面板里补设（需要原口令），补设后口令仍然有效。已存拓扑的字段、节点 ID、组引用和显式填写的地址保持不变，编译结果不变。

## 不防什么

- 局域网内已经拿到面板口令或管理员密码的人：他们拥有全部服务器的控制权。
- 网关宿主的 root 用户：可以读取全部凭据。
- 面板与浏览器之间是明文 HTTP（只在局域网或 SSH 隧道内）。不要把面板端口转发到公网；远程管理请走远程接入（WireGuard）或 SSH 隧道。
- 浏览器所在设备被入侵：面板口令保存在该标签页的 sessionStorage，关闭标签页即清除。
