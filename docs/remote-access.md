# 远程接入

出门在外的手机、笔记本可以经一个 WireGuard 接口连回家里的网关。连上后，网关把它们当作局域网里的另一台设备：同一套分流、DNS 劫持、地区组出口和 `inet meridian_guard` 兜底表。默认关闭。设计细节见 [架构](architecture.md)「远程接入」。

## 它做什么，不做什么

- 网关上多一个接口 `mra`，监听你指定的 UDP 端口。每台设备是 `mra` 上的一个 peer，有自己固定的地址（默认地址池 `10.67.0.0/24` 和 `fd67::/64`，网关自己用 `.1` / `::1`，也是设备的 DNS）。
- 设备的流量从 `mra` 进入网关后和局域网流量一样处理：国内直连（改写成网关的局域网地址再交给 ROS），境外经地区组的隧道出去，分不出类的丢弃。从 `mra` 来的 53/853 一律由网关本机解析。
- 面板**不碰路由器**，也不猜你的公网地址：Endpoint（DDNS 名或地址）和端口由你填写。
- 面板**看不到**手机能不能真的从外网连回来。这只能用真实手机验证（见最后一节）。

## 两种模式

| 模式 | 客户端 `AllowedIPs` | 覆盖范围 |
| --- | --- | --- |
| 全部流量（`full`） | `0.0.0.0/0, ::/0`，DNS 是网关 | 设备的全部流量都经 Meridian 分流和防泄露规则 |
| 仅回家（`home`） | 只有家里的局域网 v4/v6 前缀和网关的两个 DNS 地址 | 只有访问家里的流量进隧道 |

**仅回家模式不保护设备的上网流量**：其余流量走手机自己的网络，不经过 Meridian 的出口、分流和防泄露规则；DNS 是否全部交给隧道里的网关取决于手机系统，不能保证。面板「防泄露」页把它列为已知限制。需要出口和防泄露时用「全部流量」。

## 在面板里配置（侧边栏「接入 → 远程接入」）

1. **入口设置**：填 Endpoint（家里公网地址或 DDNS 名）和监听端口（UDP，不能和网关上已有的隧道、WSS、面板、DNS 等端口冲突，面板会拒绝）。需要时改地址池、MTU（默认 1380）、Keepalive（默认 25 秒）。地址池里有设备后不能再改池。打开开关并保存；第一次保存时面板生成网关这一侧的密钥（私钥只在 `meridian-secrets` 卷里，拓扑里只有公钥）。
2. **添加设备**：起个名字，选模式，可选预共享密钥（默认带）。面板当场生成这台设备的密钥对，弹窗里显示**唯一一次**完整配置：文本、下载文件和二维码（二维码在浏览器里生成）。关掉弹窗后面板不再能给出这份配置——设备私钥没有保存在任何地方。
3. **安装**：设备的增删、停用、重新生成都只改面板的数据，要到「运维 → 部署」点「安装到本机」才生效。安装把新的 peer 集合写进网关的 `/etc/wireguard/mra.conf` 并 `wg syncconf`，停用或删除的设备在这一步从接口上消失。
4. **路由器**：按「路由器上需要做的事」卡片在路由器上手工加一条 UDP 端口转发：外部端口 → 网关局域网地址的同一端口。IPv6 直连时，还要在路由器防火墙放行到网关全局 IPv6 地址的这个 UDP 端口。面板不连接路由器，也无法从外面确认转发生效。
5. **导入**：在手机 WireGuard App 里扫描二维码或导入文件。

### 重新生成

配置丢了、手机换了、怀疑泄露时，在设备行点「重新生成」：新的密钥对和新的预共享密钥，地址不变，同样只显示一次。旧配置在下一次「安装到本机」后失效。改了 Endpoint、端口、网关密钥、地址池、模式、MTU 或 Keepalive 后，设备行会提示「配置已过期」，也要重新生成并重新导入。

### 关闭

关掉开关并安装：网关删除 `mra` 接口、配置和全部相关规则；设备记录和密钥留在面板，重新打开后原配置继续可用。关闭后旧地址池的黑洞路由和 `iif mra unreachable` 规则会留到下次重启，它们只会丢包；`meridian-verify.sh` 把后者显示为 `INFO remote_leftover`，并在 `mra` 接口仍然存在时报 `FAIL remote_absent`。

## 安全性质

- **与局域网同等对待**：同一套分类、DNS 劫持、DoH 拒绝、策略路由和兜底表；境外标记的流量只能进网关的 WireGuard 隧道接口，`mra` 不在其中，所以境外流量不会从 `mra` 或局域网口出去。
- **设备之间不互通**：从 `mra` 进、再从 `mra` 出的包被兜底表丢弃。家里的主机可以访问设备（两条窄放行），设备可以访问家里的主机。
- **面板不对设备开放**：面板端口只接受局域网地址，设备地址池不在其中。
- **监听端口只在局域网口接受**（包括 ROS 转发进来的 IPv6），其他接口上的同一端口丢弃。
- **秘密**：网关私钥和预共享密钥在 `meridian-secrets` 卷里（0700 / 0600，没有静态加密），编译产物、快照、预览、差异和 API 里只有占位符，只在「安装到本机」时写进 0600 的 `mra.conf`。设备私钥只在创建或重新生成的那一次响应里出现。
- 运行状态（最近握手、流量）经 `meridian-host` 的只读动作读取，只比对公钥，从不读取 `wg show … dump`。

## 验证

自动化与集成层面已经有的：

- `go test ./internal/compile`：守卫逐条求值、分类、DNS、入站端口、地址改写、路由、启动顺序、关闭时编译结果逐字节不变；`TestVerifyScriptRemoteAccess` 用桩程序检查 `meridian-verify.sh` 对远程接入的判定。这些只证明生成的文本和脚本逻辑。
- `TestNetnsReloadNoLeak`（Linux、root、`MERIDIAN_NETNS_TEST=1`）用 veth 代替 WireGuard 模拟一台远程设备，在加载、重载、失败注入、地区组切换和只剩兜底表时检查设备流量不以原地址到达 ROS。**它在加入远程接入之后还没有在 Linux 上跑过**；`docs/evidence/2026-11-12-debian13/` 里的日志不覆盖远程接入。
- 网关上 `sudo /usr/local/sbin/meridian-verify.sh`：打开时核对 `mra` 存在且 up、监听端口、对端公钥恰好是已启用设备（只比较公钥）、兜底表入口是 `{ 局域网口, mra }`、DNS 劫持和 DNS 白名单含设备池、端口只在局域网口放行、`iif mra unreachable`、设备池路由、地址改写。

必须由人用真实设备做、并把截图和输出存档的（`meridian-verify.sh` 打印为 `PENDING-HUMAN`，面板「防泄露」页为「待人工签收」）：

1. **路由器转发**：只读查看路由器上的 UDP 转发规则（外部端口 → 网关局域网地址），截图存档；确认 Endpoint 解析到家里当前的公网地址。
2. **手机，蜂窝网络，全部流量模式**：关掉 Wi-Fi，导入配置并连接。
   - WireGuard App 显示握手成功、有收发字节；面板设备行显示最近握手。
   - 在手机浏览器打开 ipleak.net / dnsleaktest.com：IPv4（和 IPv6，如果有）出口是默认地区组的出口地址，DNS 服务器里没有运营商的解析器。
   - 访问一个国内站点，确认它按国内直连（例如 ip.cn 显示家宽地址）。
   - 打开面板地址（`http://<网关局域网地址>:8787`）必须**打不开**。
   - 两台设备同时连上时，一台 ping 另一台的设备地址必须不通。
3. **同一台手机，仅回家模式**：家里的局域网主机和网关 DNS 可达；在签收记录里写明其余上网流量走运营商、不受 Meridian 保护。
4. **IPv6**：隧道里的 IPv6（设备池地址）可用；Endpoint 有 AAAA 记录时，从支持 IPv6 的网络拨入也试一次。
5. **停用 / 重新生成**：停用一台设备并安装后，它的旧配置连不上；重新生成后旧配置连不上、新配置能连。

没有这些存档记录之前，远程接入在真实网络上的行为仍是「未验证」。
